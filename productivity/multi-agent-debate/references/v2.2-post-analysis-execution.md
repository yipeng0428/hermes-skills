# v2.2 Post-Analysis Execution Pattern

> 新增原因：2026-07-15

技能实际使用中发现：分析结束后用户常说"去吧，去执行这三个任务"。当前技能的分析框架与执行框架是分离的两部分，缺少从分析结论到实际执行的**衔接流程**。

## 场景

```bash
用户：群智模式：检测本系统可修复/可增强环节
[技能派发5个子Agent运行闪电/辩论/专家分析]
[技能输出终审报告]
用户：去吧，去执行这三个任务
```

## 问题

- 分析框架擅长诊断和出方案
- 执行框架擅长让子Agent分工干活
- **但中间缺一步**：用户看完分析后说"执行吧"，如果重新派发Execute子Agent，它们缺乏分析阶段的上下文（根因数据、cron ID、error状态）
- 应直接用用户在分析阶段展示的底层数据（cron list、script路径、provider状态）直接操作Hermes工具（cronjob run/update/pause、terminal cp、read_file等）
- 不需要重新派发Execute子Agent——主Agent已有全部context，直接执行即可

## 正确流程

```bash
分析阶段 → 终审报告 → 用户下达执行指令
                            ↓
              [主Agent直接操作Hermes工具]
              - cronjob(action=update) — pin provider/cron配置
              - cronjob(action=pause)  — 暂停僵尸任务
              - terminal(cp/mv)       — 修复脚本路径
              - cronjob(action=run)    — 验证修复
                            ↓
              [向用户汇报每个动作状态]
              - ✅/❌ + 一句话说明
              - iLink等平台硬限制明确标注（预期内）
              - 需要用户手动做的步骤列出
```

## 注意事项

1. **分析数据和执行上下文不隔离**：分析阶段展示的cron list/status等数据就是执行时的target，不需要重新获取
2. **平台硬限制标预期**：iLink 30秒冷却是平台服务端限制，delivery失败属预期内，不是修复失败
3. **静默执行+汇报**：不需要反复确认，做完后统一汇报
4. **不需要子Agent执行简单操作**：配置漂移修复、路径复制、僵尸暂停这些简单操作不需要派发Execute子Agent——直接操作Hermes工具更快更准

## 测试记录

### 测试（2026-07-15 实际运行）
- **用户指令**：检测系统 → 我说"去吧执行三个任务"
- **完成**：锁定4个provider漂移cron + 修复watchdog路径 + 暂停2个僵尸任务
- **验证**：`morning-system-check` 运行成功，`notion-sync` 运行成功（delivery仍iLink限流=预期内）
- **耗时**：<3分钟（vs 派发Execute子Agent预计5-10分钟）
