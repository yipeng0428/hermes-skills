# SMA · Solo Multi-Agent（单线多智协同）

> 一个门面，多个大脑。用户看到单一连贯输出，后台多AI能力堆叠。

## 核心哲学

```
旧辩论模式：A说+B说+C说 → 主持人总结 → "这是三种观点"
SMA模式：   A擅长+B擅长+C擅长 → 融合提炼 → "这是一个精品"
```

**一句话区别**：辩论输出"分析"，SMA输出"成品"。

---

## 触发规则

### 自动判断（门面AI自动决定是否SMA化）

| 任务复杂度 | 行为 | 示例 |
|-----------|------|------|
| ⚪ 极简 | 单模型直回，不调多用 | "改下这个尺寸" |
| 🟡 中等 | SMA串行精炼2轮 | "写一段详情页文案" |
| 🟠 中高 | SMA并行融合3-4路 | "分析这个竞品的设计策略" |
| 🔴 高难 | SMA增强逼近，冲顶级水平 | "设计的品牌升级策略" |
| ⚫ 极限 | SMA全链路 + 用户确认终稿 | "进入角色面试，我要做重大决策" |

### 手动触发词

用户说以下任意词，强制进入：
- **"SMA"** / **"SMA模式"** / **"单线多智"** / **"单线模式"**
- **"堆叠"** / **"叠加"** / **"AI叠加模式"** / **"多AI一心"**
- **"精品模式"** / **"最高质量"** / **"全力以赴"**
- 说"让我看看SMA给出的答案" → 显式触发

## 三种执行模式

### 模式A：串行精炼（Serial Refinement）

**结构**：草稿 → 纠错 → 润色 → 输出

```
AI-1 (生成初稿) → AI-2 (质检+补充) → AI-3 (润色+统一语调) → 最终输出
```

**适用**：文案/方案/长文/设计说明/报告

**专门角色匹配**：

| 阶段 | 角色 | 模型推荐 | 核心作用 |
|------|------|---------|---------|
| 第1棒 | 创作者 | DeepSeek / GPT | 产出完整初稿骨架 |
| 第2棒 | 质检员 | Claude / LongCat | 补充遗漏、纠正错误、加深度 |
| 第3棒 | 表达官 | GPT / Claude | 统一语调、润色措辞、情感节奏 |

**成本**：约2.5-3倍单次对话 token
**速度**：30-50秒

### 模式B：并行融合（Parallel Ensemble）

**结构**：同一任务拆成维度 → 各AI并行处理 → 门面AI汇总为统一成品

```
任务："分析竞品X的设计策略"
       ↓
┌─────────────────────────────────────────┐
│ AI-1: 视觉设计维度（配色/排版/构图）     │
│ AI-2: 商业策略维度（定价/定位/渠道）     │
│ AI-3: 文化洞察维度（趋势/受众/故事）     │
│ AI-4: 技术执行维度（材质/工艺/落地性）   │
└─────────────┬───────────────────────────┘
              ↓
汇总融合 → 去重去矛盾 → 一份多维度完整分析
```

**适用**：复杂分析/竞品报告/策略文档/多维决策

**成本**：约3.5-4倍单次对话 token
**速度**：15-25秒（并行发射）

### 模式C：增强逼近（Enhanced Approximation）

**结构**：门面AI先答 → 挑战者找漏洞 → 门面AI迭代 → 再挑战 → 终稿

```
门面AI输出V1 → 挑战者（对角落模型）找漏洞 → 门面AI读漏洞输出V2
→ 再挑战 → 门面AI输出V3（终稿）
```

**适用**：高 stakes 决策/投资判断/品牌策略/晋升答辩

**关键**：挑战者必须是用不同训练数据集的强模型（否则"自己挑战自己"无意义）

**专项能力匹配表**：

| 门面AI（最懂问题类型） | 挑战者（训练分布差异最大的模型） |
|------------------------|-------------------------------|
| DeepSeek 中文文案 | Claude / GPT-4 |
| Claude 逻辑分析 | GPT-5 / DeepSeek |
| GPT-5 创意发散 | Claude / Mistral |
| LongCat 中文商业 | DeepSeek / Claude |

**成本**：约3倍单次对话 token
**速度**：40-60秒

## 自动决策树（门面AI收到问题后的判断流程）

```
收到用户问题
    │
    ├─ 简单任务？（<100字回答/修改/判断）
    │   └─ YES → 单AI直回
    │
    ├─ 手动触发词出现？
    │   └─ YES → 强制进入SMA
    │
    ├─ 任务复杂度评估：
    │   │
    │   ├─ 需要创意+文字输出？ → 串行精炼
    │   ├─ 需要多维度分析？   → 并行融合
    │   ├─ 需要高可信决策？   → 增强逼近
    │   └─ 复合材料（分析+执行）？ → 串行+并行混合
    │
    ├─ 预算/Gate检查：
    │   ├─ token余额充裕 → 全量
    │   └─ 余额偏低 → 精简版（少AI/少轮次）
    │
    └─ 输出格式约定：
        ├─ 不告诉用户"这是多AI融合结果"
        ├─ 直接给出最高质量成品
        └─ 附加附录（可选）："参与AI：X个，融合模式：Y"
```

## 多AI能力堆叠（异质化原则）

> **关键：参与SMA的AI必须在训练数据/擅长领域上有明显差异。**

### 推荐组合

| 任务类型 | 组合1（国内系） | 组合2（国际系） | 组合3（混合系） |
|---------|---------------|----------------|----------------|
| 文案撰写 | DeepSeek + LongCat | Claude + GPT | DeepSeek + Claude |
| 策略分析 | DeepSeek + InternLM | Claude + Mistral | GPT + DeepSeek |
| 设计方案 | LongCat + DeepSeek | Claude + GPT | 三者混搭 |
| 数据报告 | DeepSeek + InternLM | GPT + Mistral | Claude + DeepSeek |
| 代码+技术 | DeepSeek + InternLM | Claude + GPT | GPT + DeepSeek |
| 创意发散 | LongCat + GPT | Claude + Mistral | DeepSeek + Claude |

### 禁止组合

| 组合 | 原因 |
|------|------|
| 同模型的两个实例 | 同质无效，浪费token |
| 两个擅长相同的模型（如GPT+ChatGPT） | 没有互补性，也不行 |
| 全部是免费弱模型 | 堆叠依然有上限 |

## 输出规范

### 标准输出格式

SMA输出的成品看起来像来自一个超级AI，而非多人讨论产物：

#### ❌ 错误输出（像辩论摘要）

> "AI-1认为应该用蓝色，AI-2建议考虑绿色，AI-3强调配色要考虑竞品区分度。综合来看..."

#### ✅ 正确输出（像一个高质量AI的精深回答）

> "基于对竞品配色格局的分析，推荐采用冰蓝色作为主色调——理由有三：
> ① 在竞品一片暖色系（橙/棕/米白）中形成温差，第一眼跳出率提升40%+
> ② 冰蓝在情感映射上同时传递「新鲜/科技/安全」三重信息，与PET抗菌材质形成认知闭环
> ③ 印刷实现成本最低（四色印刷直接出片，无需专色）"

### 附录元数据（可选显示）

```
---
📊 本次SMA：3 AI融合 | 模式：并行融合 | 维度：视觉+商业+文化+技术 | 回应耗时：22秒

```

## Hermes 中的实际执行实现

### 通过 Multi-Model Runtime（terminal + curl）

> 由于 `execute_code` 不支持API调用，所有SMA调用通过 `terminal` 执行脚本。本技能已提供两个模板文件，复制后调整 provider/model 参数即可。

**模型选型参考** → `references/model-matching-table.md`（含本机所有 provider env var 与擅长领域）

#### 模板1：串行精炼（Serial Refinement）

```bash
bash templates/sma_serial.sh "你要写的任务或问题" /c/Users/win10
```

#### 模板2：并行融合（Parallel Fusion）

```bash
bash templates/sma_parallel.sh "你要分析的问题" /c/Users/win10
```

**执行前检查清单**：
- [ ] `source ~/.hermes/.env` 一次（shell 会话级生效）
- [ ] 调用的 provider env var 存在且非空
- [ ] 不要将 `DEEPSEEK_API_KEY` 传给 jbbtoken（两个 key 独立）
- [ ] mistral 当前可能 401（key 过期），需要有备选

### 为什么用错模型做SMA = 浪费钱

| 维度 | 推荐模型 | 不推荐 | 原因 |
|------|---------|--------|------|

## 与现有技能的边界区别

| 维度 | SMA（本技能） | Mixture-of-Agents | Yuanbao | Multi-Agent Debate |
|------|---------------|-------------------|---------|-------------------|
| **交互感知** | 单一AI，聊家常多层精 | 多层显性，各层输出 | 群聊感，多人辩论 | 三模式框架感 |
| **输出形式** | 一个精品成品 | 一层层升级的版本 | 辩论摘要+投票 | 三方对比+终审 |
| **AI间关系** | 互补叠加，看不到对方 | 后层引用前层 | 真实辩论，能看到对方 | 独立分析后对比 |
| **核心优势** | 高质成品，自然体验 | 深度打磨完整方案 | 战略碰撞出新知 | 决策分歧可视化 |
| **token消耗** | 中等（2-4倍） | 高（3-6倍） | 偏高（3-5轮辩论） | 中等（3路子Agent） |
| **时间延迟** | 15-50秒 | 30秒-3分钟 | 1-3分钟 | 20秒-2分钟 |

### 选择指南

```
需要快速得到一份高质量答案
  └→ SMA（单线多智）

想要看到分析过程逐步升级
  └→ MoA（多层精炼）

需要对一个问题做多角度辩论
  └→ Yuanbao / Multi-Agent Debate

需要多个专家角色完成不同子任务
```

## 验证清单

在执行SMA时，门面AI必须确认：

- [ ] 复杂度评估正确（不是所有问题都需要SMA）
- [ ] 所有参与AI在训练数据/擅长领域上有差异
- [ ] 融合后成品读起来像一个专家写的（不是拼凑感）
- [ ] 没有模型间的矛盾未被裁决
- [ ] 最终输出是"可用的精品"（不是"多视角罗列"）

---

## 注意事项

1. **不要滥用SMA**：简单问题用SMA = 浪费token + 延迟体验
2. **异质性是灵魂**：相同模型的第二次调用 ≠ 更多知识
3. **门面AI不降级**：用户永远不知道后台有几个AI，体验永不打折
4. **失败优雅降级**：如果某AI调用失败，在其他AI输出基础上补充，不让用户感知
5. **不要过度承诺**：SMA逼近GPT-5.6，但物理极限存在。量力而行
6. **成本透明（可选）**：如果用户使用"SMA状态"，显示本次调用了几个AI、消耗多少token

## 与Multi-Model Runtime技能的协作

SMA技能调用执行层面完全遵循 `multi-model-runtime` 技能的规则：

1. **必须用terminal + curl**（execute_code不支持API调用）
2. **必须先source .env文件**（获取API Key环境变量）
3. **并行调用必须写独立文件+wait**（防止输出交错）
4. **必须处理provider特有trap**（deepseek要sk前缀、jbbtoken不要混淆等）
5. **失败必须显式报告**（哪个专家角色缺失）
