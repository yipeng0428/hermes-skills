# SDOF（状态约束分派框架）

## 触发关键词
- "状态约束" / "阶段验证" / "SDOF" / "意图路由"
- "约束状态机" / "流程管控" / "阶段门禁" / "前置条件"

## 核心理念
多Agent协作不是"自由讨论"，而是在严格业务流程约束下执行。
每个Agent调用都有前置条件、后置条件、阶段约束。

## 何时不该用

| 场景 | 原因 | 替代方案 |
|------|------|---------|
| 简单一次性任务 | 状态机建设成本>收益 | 直接用 `design-agent-team` |
| 需要灵活创意的任务 | 过度约束会限制创意 | 用 `flow-state-engineering` |
| 学习阶段 | 先理解流程再固化 | 用 `cognitive-externalization-loop` |
| 快速迭代原型 | 状态机会拖慢速度 | 用 `mixture-of-agents` |

## 快速上手（3分钟）

1. 对AI说：`状态机：{你的任务}`
2. AI返回：任务流程+阶段划分+前置条件
3. 确认后开始执行

## 三核心组件

### 组件1: 意图路由器
识别用户意图，路由到正确的处理流程。7B路由器准确率80.9%。

### 组件2: GoalStage有限自动机
```
需求分析 → 方案设计 → 审核确认 → 执行输出 → 验收
```
每个状态转换有必须满足的条件。

### 组件3: SkillRegistry
每次工具调用前后的可审计执行控制。

## 执行流程（设计师版标准流程）

```markdown
状态1: 需求接收
  ├─ 前置条件: 需求文档完整
  └─ 后置条件: 需求理解正确（复述确认）

状态2: 竞品分析
  ├─ 前置条件: 至少5个竞品样本
  └─ 后置条件: 分析报告包含3个趋势+3个机会

状态3: 创意发散
  ├─ 前置条件: 分析报告通过审查
  └─ 后置条件: 至少3个不同方向+每个方向有3个参考

状态4: 方案筛选
  ├─ 前置条件: 创意方向齐全
  └─ 后置条件: 选定1个方向+备选1个

状态5: 方案执行
  ├─ 前置条件: 人类确认所选方案
  └─ 后置条件: 完成主视觉+延展到所有平台尺寸

状态6: 质检发布
  ├─ 前置条件: 质检Agent审查0问题
  └─ 后置条件: 文件归档+交付文档
```

## 真实案例：万凯新品详情页设计

```
状态1: 需求接收
  ├─ 前置: 拿到设计brief（包含产品信息+目标受众+营销目标）
  └─ 确认: AI复述需求，人类确认无误

状态2: 竞品分析
  ├─ 前置: 至少5个竞品样本
  └─ 输出: 竞品设计趋势报告（3个趋势+3个机会点）

状态3: 创意发散
  ├─ 前置: 竞品报告通过审查
  └─ 输出: 3个创意方向（视觉冲击/技术参数/信任背书）

状态4: 方案筛选
  ├─ 前置: 3个方向各出3版参考
  └─ 确认: 人类选"视觉冲击"为主方向

状态5: 方案执行
  ├─ 前置: 人类确认"视觉冲击"方向
  └─ 输出: 主视觉设计+淘宝主图+详情页+拼多多主图

状态6: 质检发布
  ├─ 前置: 质检Agent审查0问题
  └─ 输出: 文件归档+交付文档+客户版提案
```

- 注入攻击阻断：100%（22次全部阻断）
- 审计召回率：88%

## 验证清单
- [ ] 是否已定义完整状态机（每个状态+前置/后置条件）？
- [ ] 每个状态转换是否满足前置条件？
- [ ] 是否执行了后置条件验证？
- [ ] 是否记录了所有状态转换日志？
- [ ] 是否有"人工越权通道"处理紧急情况？

## 与相关技能联动
- 配合 `budgeted-act-defer` 为每个状态设定错误预算
- 配合 `grade-routing` 为每个状态选择最优模型
- 配合 `multi-agent-swarm` 让每个状态由专门Agent负责

## 注意事项
1. **状态机设计是核心**：设计错了，后面全错
2. **前置条件宁可严一点**：比"太松导致产出质量问题"好处理
3. **不要在运行时修改状态机**：流程问题在流程外解决
4. **保留人工越权通道**：紧急情况人类可以跳过约束
