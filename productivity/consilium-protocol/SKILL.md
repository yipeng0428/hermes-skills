# Consilium Protocol（BFT认知协议）

## 触发关键词
- "BFT审议" / "认知人设" / "模型审议" / "consilium"
- "多角度审议" / "认知偏差检测" / "盲点发现"
- "便宜模型能做到吗" / "低成本方案"

## 核心理念
关键发现：免费边缘推理模型 + 合适的认知人设 ≈ 前沿模型(10.69 USD)
模型能力的差距，可以被**认知人设（Persona Engineering）**弥补。

## 何时不该用

| 场景 | 原因 | 替代方案 |
|------|------|---------|
| 简单执行任务 | 审议成本>收益 | 直接用 `design-agent-team` |
| 需要快速决策 | 审议需要时间 | 用 `budgeted-act-defer` 快速分级 |
| 已有明确共识 | 不需要审议 | 直接执行 |
| 纯创意发散 | 审议会限制创意 | 用 `allocation-economy` |

## 快速上手（2分钟）

1. 对AI说：`审议：{你的议题}。4个人设。`
2. AI返回：4个不同人设的独立观点
3. 对AI说：`交叉质疑：让每个人设回应对其他观点的质疑。`
4. AI返回：修改后的观点+改变说明
5. 对AI说：`样本外验证：对关键声明做事实核查。`
6. AI返回：验证结果+盲点清单

## 三角色架构
| 角色 | 功能 | 人设 |
|------|------|------|
| 提案者（Proposer） | 提出方案 | "追求创新的产品经理" |
| 验证者（Validator） | 质疑审查 | "挑剔的质检专家" |
| 整合者（Integrator） | 综合裁决 | "平衡创新和风险的CEO" |

## 认知人设工程（关键操作）

人设模板：
```markdown
"你是一个具有{认知特征}的{职业角色}。你的思考方式是{思维方式}。
你特别关注{关注点}。你总是习惯从{视角}看问题。
你对{某类风险}非常敏感。你的价值观偏向{某项原则}。"
```

常用人设库：
```markdown
| 人设 | 认知特征 | 关注点 |
|------|---------|--------|
| 创新推动者 | 乐观、增长导向 | 机会、市场潜力 |
| 风险管理者 | 保守、安全导向 | 成本、失败概率 |
| 用户代言人 | 共情、体验导向 | 用户体验、需求匹配 |
| 务实执行者 | 落地导向 | 团队能力、时间成本 |
| 挑剔质检师 | 批判性思维 | 漏洞、风险、逻辑矛盾 |
| 数据分析师 | 理性、证据导向 | 数据、统计、趋势 |
```

## 执行流程

### Step 1: 分配认知人设
```
Agent A（创新推动者）：关注机会和增长潜力
Agent B（风险管理者）：关注成本、失败概率和止损条件
Agent C（用户代言人）：关注用户体验和需求匹配
Agent D（务实执行者）：关注团队能力和落地可行性
```

### Step 2: 独立审议
`"作为{人设}，你对这个议题的看法是什么？列出3个核心论点和对应的证据"`

### Step 3: 交叉质疑
`"你已经看到了其他专家的反对意见。请修改你的答案，标注：改变了什么/没改变什么/为什么"`

### Step 4: 样本外验证
对审议中的关键声明，进行独立事实核查：
```
"请独立搜索验证以下声明是否属实：{声明1}, {声明2}..."
```

## 真实案例：万凯是否做小红书店铺

```
议题：万凯包装是否应该开小红书店铺卖闽南文创？

Agent A（创新推动者）：
  "应该做！小红书是闽南文创的最佳渠道，月活用户2亿+，年轻女性占比70%..."
  
Agent B（风险管理者）：
  "谨慎做。初期投入3000-8000元，ROI不确定，库存风险..."

Agent C（用户代言人）：
  "用户需要的是'有故事的包装'，不是'工业产品'。需要重新定位..."

Agent D（务实执行者）：
  "团队目前只有1个美工，产能有限。建议先外包内容创作..."

交叉质疑后：
  A改变了：同意"先小规模测试"（原来主张全面投入）
  B改变了：同意"3000元以下风险可控"（原来主张不做）
  C没改变：坚持"需要重新定位"
  D改变了：同意"可以先用现有产品试水"

样本外验证：
  "小红书文创店铺月销过万" → 验证：属实（找到5个案例）
  "闽南文创在小红书搜索量增长" → 验证：属实（同比增长45%）

最终共识：有条件地做，3000元冷启动，先测试3个月
```

## 验证清单
- [ ] 是否分配了至少3个不同认知人设？
- [ ] 每个观点是否有证据支撑？
- [ ] 是否执行了交叉质疑（标注改变/不改变/为什么）？
- [ ] 是否对关键声明做了样本外验证？
- [ ] 是否记录了发现的盲点？

## 注意事项
1. **人设冲突是设计目的**：一致的产出=没有审议价值
2. **人设要具体**：不能用"你是一个专家"，要用认知特征+思维方式+价值观的具体描述
3. **样本外验证不可省略**：审议结论需要用外部数据源交叉验证
4. **记录盲点发现**：审议的价值在于发现盲点，而不仅仅是达成共识
